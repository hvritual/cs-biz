# 前端设计与接入约定

技术选择仍为 [ADR-0001 提案](../../doc/architecture/adr/0001-frontend.md)。后续实现围绕以下边界组织：

| 层 | 放置内容 | 约束 |
| --- | --- | --- |
| 应用外壳 | 导航、布局、页签、用户及租户切换 | 业务页面不重新实现壳层 |
| 平台能力 | session、theme、locale、access、HTTP | 只提供必要稳定接口，不为所有组件再造一层框架 |
| 业务模块 | 租户、模块开通、成员、角色、客户等 | 按用户任务组织页面与状态，避免堆成一个 system 目录 |
| 组件库 | 选定的 Ant Design Vue 或最终决定的库 | 保持一个主要组件库，减少视觉与主题分歧 |
| API 适配 | 从全局契约生成的类型与 HTTP 适配 | 统一错误码、分页、取消请求、关联 ID |

## 动态换肤

建议首期支持 light / dark / system、有限品牌主色和舒适/紧凑密度。CSS variables、组件库 Theme Token 和图表色板必须来自同一主题状态，浮层也要覆盖。租户品牌只允许约定 token 和受控资源；不接收任意 CSS / JavaScript。

建议优先级：产品默认值 → 租户可配置 token → 当前用户在该租户可覆盖的偏好。租户固定品牌字段不能被个人配置覆盖。持久化键至少包含用户、租户和配置版本；访客偏好独立。首屏先恢复必要偏好，再渲染应用，避免闪变。跨租户的品牌色、Logo 不应残留。

## 国际化

建议首期完成 `zh-CN`、`en-US`。UI 文案、菜单 `titleKey`、校验、组件库语言、日期格式和错误提示都需要覆盖。语言、时区、货币是三个独立设置；金额与数量保留原始值，展示时格式化。服务端返回稳定错误码与参数，不要求前端解析中文文本。API、审计和数据库字段不使用翻译后的标签做主键。

新语言按语言包和覆盖验收扩展；RTL 和复杂输入需求单独评估。模板声称支持国际化不等于业务已完成所有目标语言。

## 访问与恢复

遵守 [Access Context 契约](../../doc/contracts/access-context.md)。使用可响应权限变化的组件或计算表达式；使用多个权限时明确 `any` 或 `all`，不能把一个权限码数组默认当作全部满足。

远程菜单只给稳定的 `viewKey`、`titleKey` 和导航元数据；本地 registry 将 `viewKey` 映射为已构建组件。不接受远程代码、任意导入路径或字符串求值。正式业务页面以有效权限码为依据，角色名称不在各页面散落判断。

页面必须说明：加载、无数据、无权限、未开通、网络失败、提交中、结果未知、成功和失败。首次提交前保存幂等键；回复丢失时使用已知操作 ID 或该键查询结果，不能盲目重复发起写请求。
