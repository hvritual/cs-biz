## 2. 已实现的本地操作

| 范围 | 操作与结果 |
| --- | --- |
| 客户 | 搜索、状态筛选、分页、查看、新建、编辑、归档；归档记录不再出现在普通客户列表，当前没有恢复归档入口 |
| 成员 | 添加账户到企业、调整角色、暂停与恢复访问；没有发送邀请、设置密码或修改既有账户个人资料的操作 |
| 角色 | 新建、查看、编辑、删除自定义角色；企业负责人角色受保护；成员仍持有的角色不能删除，包括暂停访问的成员 |
| 企业资料 | 更新企业名称、联系人、联系电话、邮箱；不创建或删除企业 |
| 应用 | 当前模块代码只有 `crm`；有申请权限的企业成员提交开通申请，平台运营单独开通或暂停应用 |
| 申请记录 | 同企业、同模块的待处理申请重复提交会返回同一条申请；平台开通后，待处理申请记为已批准，并记录处理时间 |
| 偏好 | 浅色、深色、跟随系统、有限主色、舒适或紧凑密度、中文或英文；按账户和企业恢复 |

模块开通是当前浏览器数据中的权益变更，不产生订单、扣费、支付或外部通知。模块暂停保留客户记录，但企业成员的客户操作会被拒绝；企业资料、成员、角色与应用中心属于独立的基础能力。

## 3. 权限与范围如何生效

每个企业请求显式携带 `subjectId` 和 `tenantId`。服务在操作执行前核对当前会话、企业成员关系及其状态，再检查模块权益和该动作的授权。页面导航与按钮来自相同能力投影，但隐藏菜单本身不承担授权职责。

| 种子角色 | 初始授权 |
| --- | --- |
| 企业负责人，`<tenantId>-owner` | 当前权限字典中的所有动作，范围为 `all`；角色不可编辑、删除，不能停用或移除最后一位活动负责人 |
| 客户观察员，`<tenantId>-viewer` | 查看工作台、全部客户、企业资料和应用 |
| 客户负责人，`<tenantId>-specialist` | 新建、编辑、归档本人负责的客户；本角色本身不额外授予查看全部客户 |

周远在青禾同时持有观察员和客户负责人角色，因此可以看到 8 条客户，但只可维护本人负责的 2 条。权限必须按 `{ action, scope }` 配对匹配，不能把“查看全部”的范围套给“编辑本人负责”。新建或编辑客户时，`own` 范围也不能通过把负责人改成别人来扩大权限。

负责人候选通过 `listCustomerOwners(context, action)` 获取，其中 `action` 只接受 `crm.customer.create` 或 `crm.customer.update`，返回最少的 `{ id, name }`。服务从当前企业的活动成员中，按该写入动作的 `all` / `own` 范围筛选：`own` 仅返回调用者本人，读取全部客户的权限不会扩大写入候选范围。新加入且尚未负责任何客户的成员可以成为候选，因而可以被分配第一个客户；停用成员会从候选中移除，新分配也会被拒绝。该接口同样核对会话、成员状态与模块权益，只读账户和没有目标企业成员关系的账户不能借它获取写入候选。

自定义角色只能授予操作者已经拥有的动作及范围。分配角色时也检查这一授权上限，不能通过分配更大的角色绕过上限；跨企业角色 ID 会被拒绝。`listRoles` 除角色读取权限外，也允许成员管理权限获取可分配角色。角色编辑器为新勾选的客户操作默认选择“本人负责”，需要明确选择才扩到“全部客户”。

`tenant.module.request` 控制开通申请；种子中仅陈予安拥有该动作。平台开通、暂停和跨企业申请列表要求会话账户具有 `platformRole: 'operator'`，不依靠企业负责人角色。张衡初始没有任何企业成员关系，平台身份不会自动变成企业成员。

新增或调整成员、角色、企业资料、应用权益会递增该企业的 `accessVersion` 并发布访问变更事件；客户变更与提交开通申请发布数据变更事件。前端重新取得访问上下文，清理动态路由与旧数据；切换账户、企业或访问代次后的晚到结果不能覆盖新页面。相关实现见 [workspace store](../apps/console/src/store/workspace.ts) 和 [useResource](../apps/console/src/composables/useResource.ts)。

## 4. 持久化位置与生命周期

| 存储 | 键或键格式 | 内容与作用 |
| --- | --- | --- |
| `localStorage` | `csbiz.s01.database.v1` | 账户、企业、成员、角色、客户、权益、申请、访问版本和幂等记录的完整本地数据库 |
| `sessionStorage` | `csbiz.s01.session.v1` | 当前标签页选中的账户；退出写入 `signed-out` |
| `sessionStorage` | `cs-biz:tenant:v1:<subjectId>` | 当前标签页内，该账户最近选择的企业 |
| `sessionStorage` | `cs-biz:pending:v1:<subjectId>:<tenantId>:<operation>` | 创建客户或成员时，结果尚未确认的输入和幂等键 |
| `localStorage` | `cs-biz:appearance:v1:<subjectId>:<tenantId>` | 当前账户在当前企业的个人偏好；平台使用 `platform` 作为企业槽位，非企业状态使用 `account` |

访客偏好使用 `cs-biz:appearance:v1:guest:account`。偏好结构与允许的主色见 [appearance store](../apps/console/src/store/appearance.ts)。底层前端偏好还有 `cs-biz-v1-dev` / `cs-biz-v1-prod` 命名空间；业务数据的版本键不随构建模式改变，但不同 origin 的浏览器存储天然分开。

刷新当前页面会从已有存储恢复业务变更，不会自动覆盖成种子。账户与企业选择按当前标签页保存；同一 origin 的标签页共享业务数据库，服务监听其 `storage` 事件以刷新访问或数据状态。个人偏好也先持久化、再应用；读取或写入被拒绝时返回 `STORAGE_UNAVAILABLE`，保存失败不会先把界面切成新偏好并宣称已保存。

业务提交先写入本地数据库，再更新内存并通知订阅者。数据库写入失败返回 `STORAGE_UNAVAILABLE` / 507，不会先给出保存成功。真实浏览器拒绝访问 `window.localStorage` 或 `window.sessionStorage` 属性时，服务初始化同样返回 `STORAGE_UNAVAILABLE` / 507，不会静默改用刷新即消失的内存存储。只有没有 `window` 的非浏览器调用才使用默认内存存储；测试也可以通过 `MockServiceOptions` 显式注入存储。

数据库 JSON 无效返回 `STORAGE_INVALID`，不会静默替换并丢弃已有内容。[启动错误边界](../apps/console/src/platform/startup-boundary.ts) 会捕获初始化失败、移除加载状态并显示业务错误与重新打开操作；不会把错误详情渲染到界面，也不会为重试自动删除原存储。

## 5. 创建操作的幂等与恢复

客户和成员创建需要调用方预先生成 key。客户端通过 [pending-command helper](../apps/console/src/utils/pending-command.ts) 在第一次提交前，按账户、企业和操作保存 key 与输入；重新打开新建表单时恢复该记录。未知结果不能通过换 key 自动重试。

服务的唯一查找范围为：

```text
[tenant domain, subjectId, tenantId, operation, key]
```

输入指纹独立存储，不属于唯一查找键。相同 key、相同规范化输入返回同一条已创建记录；读取的是该记录当前有权查看的状态，不是缓存的旧响应快照，后续编辑不会因重放而回滚。相同 key、不同输入返回 `IDEMPOTENCY_CONFLICT` / 409。不同企业、不同账户、不同操作互不复用结果。

幂等重放仍需当前调用者有权执行该动作，并在读取客户结果时检查当前可读范围。调用者停用、失去创建权限或应用关闭后，不能借旧 key 绕过访问限制。另一方面，原命令已经完成后，负责人后来停用或成员原角色被替换、删除，不应把原命令误当成新的创建：服务先查历史结果，仅对新命令检查负责人和分配角色的当前可用性。

客户端收到成功回执后清除相应 pending；即使已经切换企业，也只清理发起请求时那个账户、企业、操作和 key 的记录。未知错误、408 超时、请求取消（`REQUEST_CANCELLED`）、幂等冲突和存储不可用均保留原记录。明确的其他 4xx 业务拒绝允许清理后修正输入。清理 pending 不会删除服务已保存的幂等结果。

默认请求延迟为 160ms。测试可以通过 `MockServiceOptions.latencyMs` 或请求的 `delayMs` 调整延迟，并用 `AbortSignal` 验证取消。服务在异步等待结束后的调用者同步执行段内重新读取存储、检查会话及授权，再执行写入；同一 JavaScript 执行域内共享存储的多个实例不会使用等待前的旧快照覆盖刚提交的撤权。

## 6. 重置本地样例

重置会删除当前 origin 下两家企业的自定义业务变更。先关闭此应用的其他标签页，避免它们继续使用旧的内存状态；需要保留的演示结果应先另行记录。

在该应用所在 origin 的浏览器开发者控制台执行以下代码，再重新载入。代码仅清理本应用的业务、会话与未完成创建记录，不清理同一 origin 的其他项目数据：

```js
localStorage.removeItem('csbiz.s01.database.v1');
sessionStorage.removeItem('csbiz.s01.session.v1');
for (const key of Object.keys(sessionStorage)) {
  if (key.startsWith('cs-biz:tenant:v1:') || key.startsWith('cs-biz:pending:v1:')) {
    sessionStorage.removeItem(key);
  }
}
location.reload();
```

重新载入时恢复初始数据库，默认账户为陈予安。个人偏好会保留；如需同时重置个人偏好，另外删除以 `cs-biz:appearance:v1:` 开头的本应用 `localStorage` 项。

服务也提供 `api.reset()` 供开发与测试直接调用：它恢复种子、清空申请与幂等记录、提高访问版本并切回陈予安，但不会自动清除独立的 pending、企业选择和偏好键。测试若使用该方法建立全新场景，应同步清理对应 pending，避免旧创建内容在重置后再次提交。

## 7. 验证入口与适用范围

从 `frontend/` 执行：

```sh
pnpm exec vitest run apps/console/src/api/mock/service.test.ts
```

[服务测试](../apps/console/src/api/mock/service.test.ts) 覆盖动作与范围配对、只读写入拒绝、租户隔离、成员停用、角色撤权、模块关闭、平台操作边界、幂等重放、初始化写入失败、两种浏览器存储属性访问被拒绝，以及共享存储的多实例并发撤权和重复创建。整个前端的类型、文案与浏览器验收由仓库实际 CI 入口统一记录；服务测试通过不代表浏览器全部交互已验收。

当前数据模型只存在于浏览器，不提供真实认证、真实后端 API、数据库隔离、跨设备同步、邮件、邀请或支付。账户选择器允许切换本地身份，用于验证前端行为，不是生产身份授权机制。

`localStorage` 是整库快照存储。已修复并验证的是同一 JavaScript 执行域的多个服务实例在异步续程之间使用旧快照的缺陷；不同真实标签页的独立执行域仍没有数据库事务、锁或冲突合并保证。跨标签页事件通知也不等于原子提交。S02 必须用真实后端授权、事务、唯一约束与受控会话承担这些边界，不能把 S01 的 Mock 测试描述成生产安全证明。
