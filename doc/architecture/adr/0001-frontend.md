# ADR-0001：前端底座采用 Vben Admin 5 + Element Plus

- 状态：`accepted`，随用户授权的 S01 技术实施采纳；验证与合并状态另行记录。
- 日期：2026-10-12
- 已明确要求：Vue、成熟组件库、动态换肤、国际化、动态菜单、权限管理。
- S00 形成推荐；2026-10-12 用户授权开始前端与 Mock 阶段，S01 已导入固定源码与依赖。真实后端和生产验证不在本决定范围。

## 采纳的选择

选择 **Vben Admin 5 + Element Plus** 作为实现底座，以真实的 `apps/web-ele` 应用为来源，在 `frontend/` 内保留可构建的 pnpm workspace，仅交付一个 console 应用。沿用上游可用的布局、主题、国际化和访问适配；业务契约放在自己的模块中。

选择依据是它已有组件库应用、主题状态与 UI 适配、动态路由和权限码能力，较适合需要多个租户工作区和长期扩展的后台。它并不提供本项目完整的租户权益、数据隔离或经营业务实现。

本次早期草案推荐过 Ant Design Vue。补查组件库正式发布后修正：Element Plus latest release 为 2.14.7（2026-09-30），Ant Design Vue 为 4.2.6（2024-11-11）。在没有既有 UI 品牌约束的新项目中，近期正式发布加上 Vben 现成适配使 Element Plus 更适合作为默认候选。发布日期不等于全面质量评分，也不足以断言 Ant Design Vue 已停止维护。发布主源见选型研究。

来源与固定版本见 [选型研究](../../research/vue-admin-selection.md)。2026-10-12 的来源观察中，最新发布为 `v5.7.0`，main 为 `4634655c621338abd97386350e5dc3d9119dab2c`；main 中部分 package 标记为 5.8.0，不能称已发布 5.8.0。实际 S01 导入身份见下文与端内锁文件；这些历史发布观察不代表今天的最新版本。

## 备选及改变选择的条件

| 备选 | 适用条件 | 代价 |
| --- | --- | --- |
| Vben Admin 5 + Ant Design Vue | 已有 Ant Design 组件资产或团队明确偏好 | 需评估当前稳定版本的发布间隔与本项目兼容需求，不能将 React antd 或其他派生库的维护状态套用过来 |
| Pure Admin 国际化精简版 + Element Plus | 团队更熟悉 Element Plus，优先较直接的应用目录和二次开发 | 当前 i18n 精简分支仍为 6.2.0，不能把完整版 7.0 的维护状态直接套用；需评估补齐差异 |
| Soybean Admin 2.3 + Naive UI | 团队接受固定 2.x 维护线与自动路由生成体系 | 官方宣布 2.3 为 2.x 最后维护大版本，3.0 将转 ubean/VeanUI，需要承担路线迁移评估 |
| Vue + 组件库自行搭壳 | 候选模板被运行验证证明耦合过重，且有维护预算 | 重新承担布局、主题、语言、路由与访问工程成本 |

## 必须适配的部分

1. 后端有效权限上下文取代演示角色与 Mock 登录。业务区采用后端菜单/权限模式，基础路由与商业模块入口明确分离。
2. 动态菜单通过本地 view registry 解析；前端不执行服务端传来的代码或任意组件路径。
3. 主题变量与组件库 token 同步；语言切换同时覆盖应用、菜单、UI 库、日期与错误信息。
4. 租户切换与撤权必须使旧路由、页签、缓存、订阅和在途结果失效。
5. 多权限判断明确 `any` / `all`。不能把 upstream 的 OR 语义当作后端权限交集。
6. 保留上游 MIT 等许可通知；在导入时盘点实际第三方依赖与资源，不自动决定本项目的发布许可。

## S01 实施与验证边界

S01 固定 tag `v5.7.0` 的 commit `63a38dce49ba109f61607994e21ba921d8e970e9`，将 `apps/web-ele` 适配为 `frontend/apps/console`。实际依赖由本仓库锁文件固定，不能把 S00 观察到的 latest release 当作本地安装版本。验证覆盖：两种语言切换、明暗主题、动态菜单、深链接恢复、按钮权限变化、未知 viewKey 拒绝、A/B 租户缓存隔离。示例数据可以用于壳层验证，但 SaaS 服务端鉴权通过需要 S02/S03 的真实 API 和隔离测试。

上游来源与实际依赖见 [来源记录](../../../frontend/doc/upstream.json)，真实命令和结果见 [S01 验证](../../evidence/S01-validation.md)。采纳技术方案、运行验证、PR 合并与部署是不同状态。
