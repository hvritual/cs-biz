# 产品范围与交付成果

## 产品目标与当前事实

为 cs-biz 交付可运行、可核对的多租户 SaaS 能力。当前实现与交付只在 [路线](../roadmap.md) 汇总：Console 本地 Mock、Authz V2 与 F1 技术 Consumer 均已存在；真实身份、持久业务数据和生产仍未完成。代码、提案、已审设计、运行与部署分别证明。

前端八类业务页面和本地数据边界见 [前端文档](../../frontend/doc/README.md) 与 [Mock 数据](../../frontend/doc/mock-data.md)。用户界面使用业务语言；本地账户不提供真实认证，成员创建不声称发送邀请，模块开通不声称支付完成。行业完整清单、商业规则与目标市场适配仍需具体任务输入。

## 首个完整业务成果：租户可真正开始使用系统

平台管理员创建租户并开通指定模块；租户负责人进入自己的工作区，建立成员、分配角色与范围；成员登录后只能看到并使用该租户已开通且自己有权使用的能力；撤销角色、停用成员或关闭模块后，API 和界面都能按规则停止访问。

这个成果同时覆盖租户管理、模块开通、成员与权限四项基础能力。其验收需要真实身份、API、持久化数据和跨端反例。当前已具备前端与技术基础，真实身份/持久 Access/业务纵向链仍按 F2–F6 推进；这一产品成果仍未完成。

## 分层产品地图

| 层 | 首批能力 | 后续扩展方向 |
| --- | --- | --- |
| 平台运营 | 租户、模块目录、开通记录、有效权益、审计 | 套餐发布、变更、额度、运营指标 |
| 租户企业中心 | 企业资料、成员、角色、数据范围、偏好 | 多组织、委派、审批、对外授权 |
| 业务工作区 | 按有效菜单进入实际业务模块 | 客户、点位、设备、合同、服务、经营报表 |
| 业务协作 | 明确参与者与资源归属 | 经销/服务/租赁关系、共享范围、结算协作 |
| 开放集成 | 版本化 API、审计关联和事件边界 | IoT、支付、通知、第三方身份与开发者能力 |

业务领域是建议地图，不能凭这张表宣称业务已经实现。咖啡机运营场景可继续采用“点位记录运营数据、客户组织经营关系”的领域划分，但必须在对应任务中给出具体指标、操作和权限范围。

## 首期角色

| 角色/身份 | 目标 | 约束 |
| --- | --- | --- |
| 平台管理员 | 管理租户与模块开通 | 不自动获得全部租户业务数据访问 |
| 租户负责人 | 维护企业、成员和授权 | 不能授予超出自身管理范围或租户权益的权限 |
| 普通成员 | 完成被授权的业务任务 | 仅访问本租户及允许范围内资源 |
| 未加入/被停用的账户 | 了解当前无法进入的原因及下一步 | 不获取租户数据 |

## 第一个闭环的前置输入

前端已先提供 `zh-CN/en-US`。完整闭环仍建议由平台人工开通模块并记录真实生效权益，使用一个具有实际 API 的业务模块验证访问边界。认证与存储方案、真实成员建立流程、审计和恢复机制需要在 S02/S03 明确并落地。

当前成员操作仅创建本地记录。后续如果采用邀请链接，需定义真实可用的受控加入流程；只有通知渠道实际送达后，才能展示对应送达结果。

进入商业化阶段前需要明确：套餐与价格、支付渠道、税费/退款语义、额度变更生效时点、试用和到期策略。当前不把“按钮打开模块”称作订阅或付费完成。
