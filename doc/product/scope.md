# 产品范围与交付成果

## 当前目标

为 `cs-biz` 持续交付可运行、可核对的 SaaS 能力，将代码、跨端契约、用户旅程和任务验收放在同一套可追踪结构中。S00 建立了仓库与设计基线；当前 [S01](../tasks/S01-frontend-mock.md) 已实现前端应用与有状态本地 Mock。

当前已落实仓库结构，以及 Vue 3、Vben Admin 5、Element Plus、主题切换、中文/英文、动态菜单和权限展示。行业完整业务清单、商业计费、迁移来源、目标市场、认证提供方和运行规模仍需后续明确；已实现两种界面语言不代表已经完成各目标市场的产品适配。

## S01 已实现的前端范围

八类页面包括工作台、客户、成员、角色、企业资料、应用中心、平台运营和个人偏好，另有本地账户选择入口。客户具备搜索、筛选、分页、查看、新建、编辑和归档；成员具备本地账号添加、角色分配、启用和停用；角色保留动作与适用范围的绑定。

企业负责人可以维护资料并提出应用开通申请，平台运营身份单独开通或暂停应用。个人偏好支持明暗与跟随系统、有限主色、密度、中文和英文。操作数据由浏览器本地服务保存，账户和当前企业按标签页隔离，创建客户与成员具有幂等重放机制。种子与实际实现边界见 [Mock 数据说明](../../frontend/doc/mock-data.md)。

本阶段用于前端交互和访问投影验证。账户选择不提供真实身份验证，添加成员不发送邮件或邀请，应用开通不发生订单、扣费或支付。本阶段没有真实后端 API、数据库、生产租户隔离或线上部署；实际代码版本与运行结论见 [S01 验证记录](../evidence/S01-validation.md)。S00 PR #1 尚未合并，S01 按设计分支上的增量 PR 交付。

用户界面使用自然、明确的业务语言；加载、空结果、不可访问、提交与保存结果都按用户任务呈现。“Mock”“未接入”“开发中”等工程状态说明只进入开发文档。

## 首个完整业务成果：租户可真正开始使用系统

平台管理员创建租户并开通指定模块；租户负责人进入自己的工作区，建立成员、分配角色与范围；成员登录后只能看到并使用该租户已开通且自己有权使用的能力；撤销角色、停用成员或关闭模块后，API 和界面都能按规则停止访问。

这个成果同时覆盖租户管理、模块开通、成员与权限四项基础能力。其验收需要真实身份、API、持久化数据和跨端反例。S01 提供前端基础，S02 身份与租户访问、S03 完整闭环尚未启动，当前不将这一成果标记为完成。

## 分层产品地图

| 层 | 首批能力 | 后续扩展方向 |
| --- | --- | --- |
| 平台运营 | 租户、模块目录、开通记录、有效权益、审计 | 套餐发布、变更、额度、运营指标 |
| 租户企业中心 | 企业资料、成员、角色、数据范围、偏好 | 多组织、委派、审批、对外授权 |
| 业务工作区 | 按有效菜单进入实际业务模块 | 客户、点位、设备、合同、服务、经营报表 |
| 业务协作 | 明确参与者与资源归属 | 经销/服务/租赁关系、共享范围、结算协作 |
| 开放集成 | 版本化 API、审计关联和事件边界 | IoT、支付、通知、第三方身份与开发者能力 |

业务领域是建议地图，不能凭这张表宣称业务已经实现。咖啡机运营场景可继续采用“点位记录运营数据、客户组织经营关系”的领域划分，但必须在对应任务中给出具体指标、操作和权限范围。

## 首期角色

| 角色/身份 | 目标 | 约束 |
| --- | --- | --- |
| 平台管理员 | 管理租户与模块开通 | 不自动获得全部租户业务数据访问 |
| 租户负责人 | 维护企业、成员和授权 | 不能授予超出自身管理范围或租户权益的权限 |
| 普通成员 | 完成被授权的业务任务 | 仅访问本租户及允许范围内资源 |
| 未加入/被停用的账户 | 了解当前无法进入的原因及下一步 | 不获取租户数据 |

## 第一个闭环的前置输入

前端已先提供 `zh-CN/en-US`。完整闭环仍建议由平台人工开通模块并记录真实生效权益，使用一个具有实际 API 的业务模块验证访问边界。认证与存储方案、真实成员建立流程、审计和恢复机制需要在 S02/S03 明确并落地。

当前成员操作仅创建本地记录。后续如果采用邀请链接，需定义真实可用的受控加入流程；只有通知渠道实际送达后，才能展示对应送达结果。

进入商业化阶段前需要明确：套餐与价格、支付渠道、税费/退款语义、额度变更生效时点、试用和到期策略。当前不把“按钮打开模块”称作订阅或付费完成。
