# 通用基础 SaaS 业务方案 · r003 待审

本轮交付的是可审阅方案。建议继续使用现有 Yunka Consumer 与 Vue/Vben Console，把首版定义为“平台开通租户和模块，负责人管理成员与权限，真实成员在正确租户完成一次合法业务操作，并能证明越权和撤销均受控”。价格、付费订阅和完整行业功能另行定义。本方案没有被用户接受，也没有形成实施授权。

这是现有 [产品范围](raw/local/doc/product/scope.md) 与 [SAAS-01](raw/local/doc/journeys/SAAS-01-tenant-onboarding.md) 的审阅视图，不取代原件。既有 F2 营销 Function-only、F3 身份/Access 的完整义务继续保留；如先做 CRM，必须显式修订相应路线，不能将其当作营销验收已完成。

## 业务背景与问题

工程已有租户、成员、角色、客户和应用开通的本地页面，能帮助审阅交互。页面背后的数据与所选身份仍在浏览器存储中；因此目前不能让真实客户依赖这些页面开展受隔离、可恢复、可审计的工作。

通用基础平台的价值是让后续业务模块共用可信身份、企业上下文、成员授权、有效模块和审计恢复；不能靠每个模块自行拼出第二套权限、租户或收费真相。平台管理员的运营权也不能自动变成读取任意租户业务数据的权利。

## 首版对象和边界

| 参与者 | 要完成的任务 | 必须保持的边界 |
| --- | --- | --- |
| 平台管理员 | 创建租户、指定负责人建立方式、人工开通或关闭模块、核对结果 | 平台权限与租户业务权限分开；没有权限不得开通；不虚构扣费和支付结果 |
| 租户负责人 | 维护企业、建立/停用成员、分配角色及动作对应范围 | 不授予超出管理范围的权限；最后负责人和并发变更受保护 |
| 普通或只读成员 | 真实登录、选择自己的企业、完成被授权业务操作 | 只能使用有效模块与合法动作，并且资源在该动作允许范围内 |
| 未加入、禁用、会话失效账户 | 看懂不能进入的原因及可执行下一步 | 不获得租户资源；恢复后重新读取当前事实 |
| 技术/运营人员 | 依据操作结果、审计和安全关联 ID 排查失败 | 排障标识不产生数据权限；日志不暴露凭据或个人资料 |

“租户”先作为 SaaS 企业工作区，不在没有业务定义时等同复杂集团、经销商关系或 IdP 的 Organization。先保留首期的中文/英文、浅色/深色与桌面布局要求，不新设移动端范围。

| 能力 | 首版建议 | 必需性的来源 |
| --- | --- | --- |
| 租户与基础企业设置 | 创建、可核对状态、负责人建立及受控恢复 | SAAS-01；未开商业模块时仍能处理有权的基础设置 |
| 模块目录及生效可用性 | 平台人工配置并回读实际有效状态；开通与授权分离 | 现有产品范围、SAAS-01 B/E/G |
| 真实身份与工作区 | 会话、0/1/N 企业、标签页独立租户、撤销与 CSRF | F3 #14 明确要求 |
| 成员、角色、范围 | 受控加入、停用/移除、最后负责人保护；动作与范围成对 | SAAS-01、F3；邀请方式仍待 P3 选择 |
| 真实业务操作 | 保留 F2 营销独立入口验证 Function 不依赖 Console Menu；随后 F4 CRM | F2 #13；不是新增全部营销/CRM 产品 |
| 恢复与审计 | 命令提交前保存恢复键，回执丢失可查；同键改参拒绝；授权后重新查询原结果 | SAAS-01 G、当前 Access 语义与已审执行边界 |

支付、套餐定价、税费、自动续费、退款、复杂配额、组织委派、跨租户共享、IoT、租赁/结算和大而全报表均为可选后续需求。本轮没有给出价格、容量、交付工期或生产 SLA；缺少组织数据时不能编造这些承诺。

## 主流程、拒绝与恢复

| 阶段 | 主路径与可观察结果 | 拒绝或失败 | 恢复要求 |
| --- | --- | --- | --- |
| 1. 租户建立 | 平台管理员确认租户和负责人建立方式，得到唯一持久记录与可查询操作结果 | 无权限、重复标识、非法负责人、并发双击 | 首次提交前已有幂等键；首回执丢失时靠这个已知键找回，不能要求用户提供未收到的操作 ID |
| 2. 模块可用 | 明确配置和影响，确认后读回生效模块 | 未发布/禁用模块、无开通权限、无效配置 | 同键同参只产生一个业务结果；不暗示扣费；关闭后新受保护请求受控拒绝 |
| 3. 首次进入 | 用户以真实凭据建立会话；0 企业显示受控说明，1/N 企业进入或选择合法工作区 | 未加入、禁用、失效会话；模块空白与无权限分别表达 | 重新认证/加入/授权后读当前上下文；不恢复旧 localStorage 权限 |
| 4. 授权配置 | 负责人核对成员、角色、所含动作及每个动作的数据范围 | 超范围委派、未知权限、最后负责人冲突 | 给出稳定原因；并发提交后读真实状态；邀请仅声明实际已发生的加入/送达事实 |
| 5. 实际业务 | 成员对持久资源执行合法操作；营销 Function 可以没有 Console Menu | 直接调 API、伪造 tenantId、跨租户、范围外、只读写入、模块关闭均拒绝且无副作用 | 受控错误与安全排障 ID；未知结果只查询状态，不把超时当失败后自动重做 |
| 6. 变化与恢复 | 切租户、撤权、成员停用或模块关闭后，UI 更新且 API 重新授权 | A 的晚到响应污染 B、另一个标签页改写当前写入目标、旧缓存越权 | 标签页工作区独立、旧 generation 丢弃、缓存按主体/租户/版本隔离；恢复后仍重验当前权限 |

授权示例必须保留：“全部客户可读 + 负责客户可写”只允许负责部分写入。不能把不同动作和不同范围分别并集，得到“全部可写”。列表、详情、写入、批量、导出和统计必须各自按对应动作范围判断。

## 可比较路线与建议

| 路线 | 收益 | 成本、反证与适用条件 |
| --- | --- | --- |
| A. 沿 Yunka 与现有 Console 补齐真实链路（建议） | 满足用户指定技术方向，复用已审 PB/Consumer/界面基础 | 真实 Access、Session、仓储、模块可用性和业务恢复仍需实现；技术探针不是这些能力 |
| B. 改用完整成熟 SaaS 平台 | 可获得更多现成模块 | ABP 等有不同语言栈、许可和商业模块边界；不能直接替换本项目而不重审成本/合同；不符合当前已指定的 Yunka 主线 |
| C. 先仅接成熟 IdP，再扩建 | 先缩小身份前置缺口，可作为 A 的最小切片 | “可以登录”不能满足 SaaS 闭环；组织身份不等同业务成员、范围或模块权益 |

建议选 A，按 C 的最小前置切片为 F2 提供真实身份与 Access；不重做已交付 F0/F1。外部方案用于比较边界与成熟模式，是否直接复用源码另核对具体许可。

## 如何判定首版有效

沿用 SAAS-01 A–I 和 F2/F3 的原义务：至少两租户及各自持久资源、不同成员状态与角色，在固定前后端/迁移版本和真实非生产环境中观察允许、拒绝、撤权、切租户和未知结果恢复。必须有直调 API 与浏览器证据，并覆盖并发、幂等、跨租户、按动作范围组合。F2 还需保留无 Menu 的营销成功、Console 深链拒绝和真实前后端 Trace。

这些是未来需要冻结并实测的出口，不是本轮已通过结果。本轮 C1–C5 只证明方案材料和源级分析已准备，C6 用户审阅仍未完成；真实 SaaS 的 DB/API/浏览器/生产结果均未验证。

待用户参与的具体选项、事实与最小回答见 [decision-requests.md](decision-requests.md)。优先确定 P1 首版范围、T1/T3 数据库与硬隔离约束、T2 已有身份资源；其余按所影响切片处理。请按本轮 r003 检查是否遗漏必需业务结果、是否越界、证据是否足够，以及是否存在过强完成声明。
