# Build admission and checkpoints

Admit only a bounded unproven result from the actual task, immutable Design handoff, complete original R/AC, current source/main and existing action authority. If already satisfied, collect fresh proof instead of manufacturing a defect. No genuine approved slice means read-only assessment, not permission to implement.

At admission read the source records, version/review bindings, allowed/forbidden paths, dependencies, resource and verification capability. Verify Function/Scope/tenant and consequential failure/recovery obligations when applicable. Risk T0–T4 follows actual behavior, not file size. Missing facts need an Owner and a concrete recovery action; Fake resources do not establish readiness.

For a module read the parent workflow’s frozen outcome contract and original lock. The module coordinator reconciles complete membership and selects the Issue; this capability does not manage the whole project. Changed acceptance/scope returns to Design; failed current evidence never permits a reduced denominator.

The Build Agent owns reconcile → admit_slice → reconcile_failure / close_slice → handoff. This reference describes checkpoint meaning only; the admit capability returns its own admission artifact and cannot dispatch successors, merge, approve or deploy. Current candidate CI and actual authorization remain separately checked.

## Task classification
Classify by behavior, not filenames:
- T0 engineering or docs: structural, compatibility and relevant regression.
- T1 presentation: tokens, layout, visuals, accessibility.
- T2 interaction: state, focus, keyboard, selection, restoration.
- T3 backend capability: tenant/auth, invariants, concurrency, failure/observable effects.
- T4 human business task: Actor -> Object -> Understand -> Action -> Result -> Recovery with end-to-end evidence.
Permissions, tenant scope, money, remote device control, deletion, quotas and asynchronous/external side effects cannot be classed below T3; human-triggered business operation uses T4. Risk unknown -> investigate, never default to low.

## Five integration checkpoints
- reconcile: on start/resume; return actual remaining goals and next action.
- admit_slice: compare locked acceptance, file scope, risk, environment and test ability.
- reconcile_failure: classify behavioral defect / test defect / environment / policy/design conflict / unknown, preserve exact attempt and evidence; consume existing project budget, do not invent a second counter.
- close_slice: show AC evidence, protected invariants and still unfinished work. Slice closed does not imply all outcomes complete.
- handoff: record exact candidate, run evidence, unverified items, blocker and one next action in the project's existing task template.
