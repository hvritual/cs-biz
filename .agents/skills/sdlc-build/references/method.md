# Build method

Receive design-to-build.json. Independently read its actual approval, immutable v2 packet, current main/source, complete module acceptance and explicit implementation/merge authority. Preserve every original AC, blocked member and invariant. Admit one bounded unproven slice; existing verified behavior requires fresh proof rather than invented code changes.

Select tdd, preserve, static, existing_verified or harness_required. TDD RED must be an assertion exposing missing behavior, not a compiler/tool/credential failure; preserve test identity through RED/GREEN and refactor only with cause. Bind changed paths to approved scope. Meaning or acceptance changes return to Design; implementation defects stay in the bounded repair loop.

Use focused checks while editing, then Fast, applicable Desktop probes and the project's trusted risk-selected final candidate gate once stabilized. Keep tester-army plus all legacy assertions and Desktop sizes. Read actual CI job results, exact-SHA independent receipt and authoritative side effects; never promote Mock/Fast/another agent's summary to stronger proof.

Independent review inspects source contract, exact diff, tests/raw logs and failure/recovery cases. The implementer does not self-approve. Merge only within actual authorization and GitHub protection, then read current main and post-merge gate; bind the immutable package to candidate/main/tree and actual byte digest. A verified/integrated package is the input to Deploy, not a deployment claim.

The Agent owns reconcile/admit_slice/reconcile_failure/close_slice/handoff and T0–T4 risk. Runtime/tenant/side-effect tasks cannot be downgraded through filenames. Continue module members within the approved graph, preserving one active candidate and existing retry budget; unknown side effects require readback. Do not poll terminal CI or replay a denied mutation.
