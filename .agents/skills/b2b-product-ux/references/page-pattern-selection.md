# 从任务选择 cs-biz 页面模式

先确认角色、任务、对象、状态、授权、风险与完成条件，再选最小交互组合。ListPage / WorkbenchPage / FormPage 是设计分类，不声称项目存在同名通用组件。

读取 [项目绑定](../PROJECT-INTEGRATION.md)，在 `frontend/apps/console/src/views/` 和 `components/` 使用 rg 检索相关页面，读实际源码与消费者。成员/角色/企业资料/客户页面都须核实；不从 biz 上游组件名推测本项目 API。没有源码索引、Page Contract 或 MetricsPage 时登记缺口，不运行虚构命令，也不为预览新增 Renderer。

| 任务 | 候选结构 | 关键义务 |
| --- | --- | --- |
| 查找、比较、选定对象 | 列表与详情 | 查看不勾选；保存筛选/焦点；选定范围明确 |
| 大批同类对象选定 | 文本粘贴/CSV + 匹配预览 | 去重、格式错误、未匹配、歧义、权限/租户、最终选定；不自动执行 |
| 对单一对象连续处理 | 工作区/主从 | 关键事实、允许动作、上下文和恢复 |
| 编辑配置 | 渐进表单 | 可信默认值、草稿、校验、影响与回读 |
| 写操作或异步结果 | 影响/确认/结果组合 | 不虚构幂等、回滚或真实后端能力 |

其余模式参考 [交互模式库](b2b-interaction-patterns.md)；其中指向 biz 的固定 URL 仅供上游案例阅读，**不作为 cs-biz 消费者证据**。选择、拒绝理由和真实缺口写入同一 [UX 分析模板](../templates/ux-contract.template.yaml)。遵循当前 Desktop/主题规范，九维不是九个固定 UI 区块。
